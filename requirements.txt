# eccodes, cusfpredict and numpy are deliberately left unpinned: they pull in
# a scientific-computing dependency tree (shapely, xarray, cfgrib, pandas)
# whose wheel availability varies across this project's container build
# matrix (amd64, arm64, arm/v7 - see .github/workflows/container.yml). On
# arm/v7 in particular, some of these have no prebuilt wheel and must build
# from source, so pip needs backtracking freedom across eccodes/numpy/shapely
# versions to find a combination that installs on every architecture.
# Pinning any one of them to a version resolved on a different architecture
# removes that freedom. (linux/386 used to be in the matrix too and was
# dropped once pandas stopped building from source there.)
eccodes
cusfpredict
numpy
# pandas comes in via cusfpredict -> xarray. There are no prebuilt pandas wheels
# for linux/arm/v7 (32-bit Raspberry Pi OS), so the container build compiles it
# from source, and pandas 3.1.0's source fails to compile there (bundled xsimd
# mismatch: "'load_unaligned' is not a member of 'xsimd'"). 3.0.6 builds fine.
# Lift this cap once a 3.1.x release builds on arm/v7 again.
pandas<3.1

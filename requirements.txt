# eccodes, cusfpredict and numpy are deliberately left unpinned: they pull in
# a scientific-computing dependency tree (shapely, xarray, cfgrib, pandas)
# whose wheel availability varies a lot across this project's 4-platform
# container build matrix (linux/386, amd64, arm/v7, arm64 - see
# .github/workflows/container.yml). On linux/386 specifically, some of these
# (e.g. shapely) have no prebuilt wheel at all and must build from source,
# and eccodes's own eccodeslib dependency has no i686 build whatsoever at
# recent versions - pip needs backtracking freedom across eccodes/numpy/
# shapely versions to find a combination where everything is either
# installable as a wheel or actually buildable from source on that
# architecture. Pinning any one of these three to a version resolved on a
# different architecture removed that freedom and broke the linux/386 build.
